About This Project

My Local Website is a personal project built to explore modern web development practices in a local, containerized environment. It started as a simple "let me get a site running in Podman" exercise and grew into a full stack that mirrors what a production deployment would look like.

The philosophy is straightforward: build it right locally, and deploying it for real becomes a boring, mechanical step instead of a rewrite. That means containers with resource limits, TLS from day one, a backend that checks its own health, and configuration that maps 1:1 to Kubernetes manifests.

The Stack

Nginx handles TLS and static file serving, proxying API requests to the backend. The FastAPI service is written in Python 3.11 and connects to PostgreSQL using psycopg2. The database runs PostgreSQL 16 on Alpine Linux, kept lean and focused.

Everything communicates over a private Podman network. No service is exposed to the host unless it needs to be — the backend's port is mapped only so health checks can reach it during verification.

The Infrastructure

Podman 4.9 runs rootless on Kubuntu 24.04. The entire stack is defined in a single compose.yaml file, with environment variables pulled from a .env file that's gitignored. A systemd user service brings the stack up automatically on login.

TLS certificates are generated with mkcert, which creates a local CA trusted by the system and by browsers. The certificate is installed into both the system trust store and the NSS database, so Firefox, Brave, and Chromium all treat the site as secure.

The Path to Production

When it's time to deploy, the compose file translates directly into Kubernetes resources: the nginx service becomes a Deployment plus an Ingress, the backend becomes a Deployment with a ClusterIP Service, and PostgreSQL becomes a StatefulSet with a persistent volume claim.

Resource limits, environment variables, health checks, and volume mounts are all already defined — the Kubernetes manifests will mostly be a reformatting exercise. The real work is setting up the ingress controller, the cluster's certificate management, and the persistent storage backend.

Design Choices

The site uses a dark theme aligned with Material Design 3 conventions: tonal surfaces for depth, an opacity-based text hierarchy (primary at 87%, secondary at 60%, hinting at 40%), and consistent spacing and type scales. The purple accent comes from the palette of the original reference image — it's the project's brand color.

Responsive design is handled with CSS clamp() functions and CSS Grid, so the layout adapts smoothly from phone screens to desktop monitors without media query breakpoints. Every interactive element meets the 44px minimum touch target size for mobile accessibility.

What's Next

The immediate next steps are tightening up the website itself — making it look polished enough to deploy publicly — and then mapping the compose stack into actual Kubernetes manifests. After that, it's a matter of picking a host, setting up the cluster, and flipping the switch.

Longer term, the plan is to add more backend functionality: real data models, authentication, a deployment pipeline, and whatever else a live site needs. The foundation is already solid. The rest is just building on top of it.
